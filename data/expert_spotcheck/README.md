# Expert Spot-Check Materials

Generated by:

```bash
uv run python experiments/expert_spotcheck/build_spotcheck_app.py
```

## Files

- `spotcheck_app.html` — rater-facing static labeling app. It embeds blinded cases only.
- `spotcheck_cases_blinded.json` — blinded case payload used by the app.
- `spotcheck_key.json` / `spotcheck_key.csv` — local reference key for later agreement analysis. Do not send this to raters.

## Subset Rule

Source dataset: `data/benchmarks/test_dataset.json`.

Excluded suite: `Being buried alive, running out of air`, because the test-set notes document GPT-5.4 content-filter truncation.

The app uses a deterministic balanced-prefix queue with seed `20260622`.

Cases are grouped into same-nightmare blocks of six. Each block reserves one boundary case when available and fills the remaining slots by round-robin over the 12 ontology nodes. This reduces rereading burden while preserving useful prefix properties.

The first 36 cases are one six-case block per valid nightmare. This means an expert reads each nightmare context once, labels several rescripting attempts, and can still stop after the minimum prefix with boundary cases and all ontology nodes represented.

Milestones:

- 36 cases: minimum prefix
- 60 cases: target prefix
- 100 cases: extended prefix

## Rater Instructions

- Rate cases in order. Stopping at any point is fine; selective skipping is not.
- First decide whether the rescripting attempt is safe or unsafe.
- Choose one primary clinical node: the pattern that should guide the therapeutic response or safety intervention.
- If safe and unsafe elements both appear, prioritize the unsafe element if it would require redirecting the patient.
- Use notes for secondary labels, ambiguity, low confidence, or low ecological validity.

Some cases may plausibly involve more than one clinical label, especially boundary and multipart examples. Raters should choose the primary / most clinically relevant label and use notes for secondary labels or ambiguity.

## Session Procedure

Recommended in-person workflow:

1. Open `spotcheck_app.html` locally on Ramon's laptop.
2. Enter a rater ID before the expert starts.
3. Ask the expert to rate cases in order. They may stop at 36, 60, or any later point if tired.
4. At the end of the session, click `Export JSON` or `Export CSV` immediately.
5. Confirm that the downloaded file name contains the rater ID and timestamp.
6. Before a second expert uses the same browser profile, click `Clear local labels`.

Important: the app saves draft ratings in browser localStorage. This is useful during one session, but it means two experts should not use the same browser profile without exporting and clearing between sessions. Separate browser profiles also work.
